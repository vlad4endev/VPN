# Тестовый план для Google Auth Fix

## Цель тестирования
Проверить корректность работы исправлений Google-авторизации, включая:
1. Задержку стабилизации Firestore (300 мс)
2. Перенаправление через onAuthStateChanged
3. Проверку custom claim admin: true в Firestore Rules

## Предварительные требования

- [ ] Код задеплоен на сервер
- [ ] Firestore Rules обновлены
- [ ] Firebase Admin SDK настроен
- [ ] Скрипт set-admin-claim.js готов к использованию

## Тест 1: Задержка стабилизации Firestore

### Цель
Убедиться, что после Google-авторизации добавляется задержка 300 мс для стабилизации канала.

### Шаги
1. Откройте DevTools (F12) → Console
2. Перейдите на страницу входа
3. Нажмите "Войти через Google"
4. Выберите аккаунт Google
5. Наблюдайте за логами в консоли

### Ожидаемый результат
```
Auth: Ожидание стабилизации Firestore-канала (300 мс) { uid: "..." }
```

### Критерии успеха
- [ ] Лог появляется в консоли
- [ ] Задержка составляет примерно 300 мс (можно замерить по времени между логами)
- [ ] Нет ошибок Firestore после авторизации

## Тест 2: Перенаправление через onAuthStateChanged

### Цель

### Шаги

2. Перейдите на страницу входа (`/` или `/#login`)
3. Нажмите "Войти через Google"
4. Выберите аккаунт Google
5. Наблюдайте за логами и URL

### Ожидаемый результат
```
Auth: Успешный вход через Google, ожидание onAuthStateChanged для перенаправления
App: onAuthStateChanged { user: true, uid: "..." }
Auth: Google-авторизация завершена, перенаправление на /dashboard
```

### Критерии успеха
- [ ] Логи появляются в правильном порядке
- [ ] URL меняется на `/dashboard`
- [ ] Используется `location.replace` (нет записи в истории браузера - кнопка "Назад" не возвращает на страницу входа)
- [ ] Данные пользователя корректно загружаются

## Тест 4: Custom Claim admin: true - Отказ в доступе

### Цель
Проверить, что пользователь БЕЗ admin claim НЕ может читать других пользователей.

### Предварительная настройка
```bash
# Убедиться, что у тестового пользователя НЕТ admin claim
node scripts/set-admin-claim.js --info test-user@example.com
# Если есть admin claim - удалить его вручную через Firebase Console
```

### Шаги
1. Выйдите из системы
2. Войдите как test-user@example.com (обычный пользователь)
3. Попробуйте открыть админ-панель напрямую через URL
4. Наблюдайте за ошибками

### Ожидаемый результат
- Ошибка: "Нет доступа к базе данных. У вас отсутствуют необходимые права администратора (custom claim admin: true). Обратитесь к администратору системы."
- Пользователь НЕ может видеть данные других пользователей
- Пользователь МОЖЕТ видеть свои собственные данные

### Критерии успеха
- [ ] Появляется сообщение об ошибке с упоминанием admin claim
- [ ] Доступ к админ-панели заблокирован
- [ ] Доступ к своему профилю работает
- [ ] В консоли ошибка `permission-denied`

## Тест 9: Firestore Rules в действии

### Цель
Проверить, что Firestore Rules корректно применяются на уровне базы данных.

### Шаги
1. Откройте DevTools → Console
2. Выполните прямой запрос к Firestore (минуя UI):
```javascript
// Для пользователя БЕЗ admin claim
const db = firebase.firestore();
db.collection('artifacts/skyputh/public/data/users_v4').get()

  .catch(error => console.error('Ошибка:', error.code));
```

### Ожидаемый результат для обычного пользователя

```

```

- [ ] Администратор с admin claim получает данные
- [ ] Правила работают на уровне базы данных
