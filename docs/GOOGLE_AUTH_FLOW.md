## 📊 Сравнение производительности

### Проверка admin через Firestore (старый способ)

```
Время выполнения: ~100-200 мс
├─ request.auth != null: ~1 мс
├─ exists(): ~50-100 мс (запрос к Firestore)
└─ get(): ~50-100 мс (чтение документа)

Стоимость: 2 операции чтения из Firestore
```

### Проверка admin через Custom Claim (новый способ)

```
Время выполнения: ~1-5 мс
├─ request.auth != null: ~1 мс
└─ request.auth.token.admin == true: ~1 мс (проверка в памяти)

Стоимость: 0 операций чтения из Firestore
```

**Выигрыш:** ~95-195 мс на каждую проверку + экономия на операциях чтения

## 🎯 Ключевые моменты

### Задержка 300 мс
- **Зачем:** Дать Firestore-каналу время стабилизироваться
- **Где:** В `processGoogleSignInUser` после создания/обновления пользователя
- **Влияние на UX:** Минимальное (не заметно на фоне других операций)

### Перенаправление через onAuthStateChanged
- **Зачем:** Избежать гонки состояний
- **Где:** В `onAuthStateChanged` после подтверждения авторизации
- **Преимущество:** Гарантированная загрузка данных перед перенаправлением

### Custom Claim admin: true
- **Зачем:** Повысить безопасность и производительность
- **Где:** В Firestore Rules для проверки прав доступа
- **Преимущество:** Невозможно обойти, быстрая проверка, нет лишних операций чтения
