# Уведомления об ошибках для администратора

Администратор может оперативно видеть сбои и исправлять их.

## Как это работает

1. **Панель «Ошибки»** в админке (раздел «Мониторинг») — список последних зафиксированных ошибок с датой, источником, текстом и уровнем (низкая / средняя / высокая / критическая). По клику можно развернуть контекст и stack.
2. **Telegram** — при настроенных токене бота и Chat ID админа (как для тикетов поддержки) каждое новое сообщение об ошибке дублируется в чат админа.
3. **Источники ошибок:**
   - **Frontend**: ошибки, пойманные Error Boundary, и необработанные promise rejection (`unhandledrejection`) — отправляются через `POST /api/report-error`.
   - **Backend**: рассылка с ошибками (часть получателей не получила уведомление), алерты подписок (dead-letter, превышение попыток активации) — вызывается `notifyAdminError()`.

## Настройка

- **Telegram**: как для тикетов — задать токен бота и Chat ID админа в настройках Telegram в админке или в `server/.env` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`). Тогда все новые ошибки будут приходить в чат.
- **Firestore**: коллекция `artifacts/{APP_ID}/public/data/admin_errors` создаётся сервером при первой записи. Правила Firestore запрещают доступ клиенту (чтение/запись только через API с проверкой админа или сервером).

## API

- `POST /api/report-error` — принять отчёт об ошибке (body: `message`, `source?`, `context?`, `stack?`, `severity?`). Опционально заголовок `Authorization: Bearer <Firebase ID token>` — тогда к записи привязывается `userId`.
- `GET /api/admin/errors?limit=100` — список последних ошибок (только для админа, Bearer + `X-App-Id`).

Хранится не более 500 последних записей; при добавлении новых старые удаляются.
